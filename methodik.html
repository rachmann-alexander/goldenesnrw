Daten & Methodik

Diese Seite beschreibt, woher die Daten auf der Karte stammen, wie sie verarbeitet werden und was beim Anzeigen im Browser passiert.

Wichtig: Die Zuordnung von Bieren zu Trinkgut-Filialen ist simuliert (deterministisch, aber nicht aus echten Bestandsdaten). Filialstandorte und Brauerei-Metadaten stammen aus den genannten Quellen.

1. Kartengrundlage

Die Landkarte wird mit Leaflet gerendert. Kartenkacheln kommen von CartoDB Voyager (basemaps.cartocdn.com). Koordinaten liegen als WGS-84 (Breite/Länge) vor.

2. Landesgrenze Nordrhein-Westfalen

Die NRW-Grenze ist eine statische GeoJSON-Datei (data/nrw-grenze.geojson), abgeleitet aus deutschlandGeoJSON (Bundesland DE-NW). Beim Start lädt der Browser die Datei per fetch() und zeichnet ein Polygon mit dezenter Füllung und gestricheltem Rand.

3. Trinkgut-Filialen (Overpass)

Nach Klick auf „Karte laden“ fragt der Browser die Overpass API ab. Gesucht werden OSM-Objekte mit brand=Trinkgut innerhalb einer Bounding Box über NRW (ca. 50,3°–52,6° N, 5,8°–9,5° E).

Bei Ausfall eines Servers werden mehrere Spiegel nacheinander versucht. Aus den OSM-Tags werden Name, Adresse und Koordinaten extrahiert.

4. Indie-Biere (Crawler & JSON)

Die Bierliste in data/biere.json wird täglich per GitHub Action erzeugt:

  1. Node.js-Crawler (crawler/crawl_trinkgut.mjs) liest Kategorieseiten von trinkgut.de.
  2. Produktnamen werden gegen eine NRW-Brauerei-Whitelist in config.mjs gefiltert.
  3. Bei zu wenigen Crawl-Treffern dient die Whitelist als Fallback-Liste.
  4. Ergebnis wird als JSON committet; der Browser lädt es beim Seitenstart.

5. Brauerei-Stammhäuser

Metadaten zu ~168 NRW-Brauereien werden in config.mjs gepflegt (Biere, Stammhaus-Adresse, Koordinaten, Geschäftsführung, Gründung, Website). Das Skript scripts/export-brauereien.mjs schreibt daraus data/brauereien.json für das Frontend.

Marker erscheinen nur, wenn lat und lon gesetzt sind. Brauereien ohne Koordinaten sind in der Sidebar sichtbar, aber nicht auf der Karte.

6. Simulierte Bier-Zuordnung zu Filialen

Trinkgut veröffentlicht kein filialgenaues Sortiment per API. Deshalb ordnet die Karte jedem Laden nach dem Laden deterministisch 3–12 Biere aus der NRW-Liste zu:

  • Pro Filiale wird ein Seed aus ID und Koordinaten gebildet.
  • Daraus folgt eine reproduzierbare Zufallsauswahl (Fisher-Yates-Shuffle).
  • Die Zuordnung ist bei gleichen Eingangsdaten immer gleich, aber nicht realitätsgetreu.

7. Bier-Verteilungsschicht (Convex Hull)

Wählt man ein Bier in der Sidebar, werden alle Filialen markiert, denen dieses Bier (simuliert) zugeordnet ist. Das „Verteilungsgebiet“ wird geometrisch abgeleitet:

  • 1 Filiale: Kreis mit 12 km Radius
  • 2 Filialen: schmaler Streifen zwischen den Punkten
  • 3+ Filialen: Convex Hull (konvexe Hülle) um alle Punkte

8. Aktualisierung & Repository

biere.json und brauereien.json werden in der GitHub Action crawl.yml täglich um 4:00 UTC aktualisiert. Filialdaten und simulierte Zuordnungen werden bei jedem „Karte laden“ live aus Overpass neu bezogen.
